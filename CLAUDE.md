# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Two things live in one tree:

1. **The app** — "Zambhala Thai Massage", a single-page marketing/booking site for a Thai
   massage spa (TanStack Start + React 19 + Tailwind v4). All of it renders from
   [src/routes/index.tsx](src/routes/index.tsx).
2. **The Grok App Builder template** — the sandbox platform harness it was scaffolded from:
   `scripts/`, `server/`, `public/__grok/`, `src/lib/{auth,db,app-data,og,multiplayer,preview-host-bridge}`,
   and the build/QA gates. This is platform infrastructure, not app code.

[AGENTS.md](AGENTS.md) is the platform's own agent contract (written for Grok Build inside the
sandbox). Its hard rules about what must not be deleted still apply here; its workflow rules
(triage, "build nothing for a greeting", brand subagents) are Grok-specific and do not govern
Claude Code sessions. Deeper docs it points at live in `.grok/references/*.md`.

## Commands

```sh
npm run dev              # Vite dev server on 0.0.0.0:8080 (the live-preview contract)
npm run build            # vite build + npm run db:migrate
npm run typecheck        # tsc --noEmit (includes src/ and server/)
npm run lint             # eslint .
npm run format           # prettier --write .
npm test                 # node --test over scripts/**/*.test.mjs + 4 src/lib TS tests
npm run preview:restart  # serve the BUILT output on 127.0.0.1:8081 (frees the port first)
npm run check:auth       # dev server vs. next build agree on VITE_AUTH_ENABLED
```

Single test file:

```sh
node --test scripts/preview.test.mjs
node --experimental-strip-types --test src/lib/auth/sign-in-gate.test.ts
```

Render QA (Playwright + Chromium are preinstalled):

```sh
node scripts/browser-smoke.mjs                       # desktop + mobile in one run, JSON verdict
node scripts/browser-smoke.mjs http://127.0.0.1:8081/ /workspace/screenshots/built.png \
  --baseline /workspace/screenshots/app-builder-preview.json
```

Exit codes: `0` clean, `1` HTTP failure, `2` console/page errors. A 200 from curl does not prove
the page rendered — read both screenshots, not just the JSON.

### Never start Vite directly

`npx vite dev` bypasses [scripts/with-app-env.mjs](scripts/with-app-env.mjs), the wrapper every
npm script routes through to merge `.grok/app-env.json` (`VITE_AUTH_ENABLED`) into the
environment. Skipping it makes dev and the built bundle disagree about whether auth exists —
exactly what `check:auth` exists to catch.

### Sandbox-only paths

`startup.sh` does `cd /workspace`, and [scripts/browser-guard.mjs](scripts/browser-guard.mjs)
only lets the Playwright scripts write screenshots under `/workspace` (and only screenshot
loopback URLs). Outside the sandbox those scripts need explicit paths or will refuse.

## Architecture

### Rendering

TanStack Start SSR through Vite 8; Nitro (`preset: "vercel"`, `serverDir: "./server"`) is added
only for `build`/`preview`. Routes are file-based under [src/routes/](src/routes/) with
[src/routeTree.gen.ts](src/routeTree.gen.ts) generated by the router plugin (never hand-edit, it
is eslint-ignored). [src/router.tsx](src/router.tsx) must keep exporting a **named
`getRouter()`** — a default `createRouter` export is rejected by the plugin.

### The app itself

- [src/lib/spa.ts](src/lib/spa.ts) holds **structure only** — `treatments` (id, category,
  per-duration price map), `categoryIds`, `timeSlots`, `testimonials` (id + guest name),
  `hours`, `contact`, plus `loadBookings`/`saveBookings`. It contains no display copy.
- **All user-facing text lives in [src/lib/i18n/dictionary.ts](src/lib/i18n/dictionary.ts)**,
  keyed by those same ids, in English and Portuguese. `en` is the source of truth:
  `Dictionary = typeof en` and `const pt: Dictionary`, so a missing or misnamed key fails
  `npm run typecheck` rather than leaking English onto a Portuguese page. Components read copy
  via `const { t } = useI18n()` — never a hardcoded string. Adding a treatment means adding its
  id to `spa.ts` and its copy to **both** language blocks.
- [src/lib/i18n/context.tsx](src/lib/i18n/context.tsx) owns language state. It deliberately
  renders `DEFAULT_LANG` ("en") on the server **and** on the first client render, then applies
  the stored/browser preference in an effect — reading `localStorage` in a lazy initializer
  instead would render Portuguese over server-rendered English and trip a hydration mismatch,
  which `browser-smoke.mjs` treats as a failure. The same effect syncs `<html lang>` and the
  meta description, which live outside React's tree.
- Careful with `t`: array callbacks in these components use `x`/`option`/`booked` as the
  parameter name precisely because `(t) => t.id` would shadow the dictionary.
- **Bookings persist to `localStorage` only** (`zambhala-bookings`; the language choice uses
  `zambhala-lang`). There is no database, no
  auth, no server function in this app — matching `.grok/app-env.json`
  (`VITE_AUTH_ENABLED: "false"`, `deploy.database: false`).
- Section components in [src/components/](src/components/) each own one band of the page and
  read structure from `@/lib/spa` and copy from `useI18n()`. State that crosses sections is
  lifted into `Home`: clicking
  "Book" on a treatment card sets a `preset` that [booking.tsx](src/components/booking.tsx)
  consumes and clears, then scrolls to `#booking`.
- [src/components/ui/](src/components/ui/) is a trimmed shadcn-style Radix layer (button, dialog,
  input, label, sheet, textarea) using `cn()` from [src/lib/utils.ts](src/lib/utils.ts).

### Styling

Tailwind v4, configured entirely in [src/styles.css](src/styles.css) via `@theme` — there is no
`tailwind.config`. Design tokens (`--color-ink/forest/moss/cream/gold`, `--font-display`
Cormorant Garamond / `--font-sans` Outfit, radii, easings) become utilities like `bg-ink`,
`text-gold`, `font-display`. Entrance animation is the `.stagger-in` class with inline
`animationDelay`; both it and `.marquee-track` are disabled under `prefers-reduced-motion`.

### Data/auth layer (pre-wired, currently unused)

Turn these on only if the work actually requires accounts or shared durable data
(see `.grok/references/data-and-auth.md` and the `.grok/skills/{auth,neon}` skills):

- [src/lib/db.ts](src/lib/db.ts) picks the backend from `DATABASE_URL`: real **Neon** when set,
  an embedded **PGLite** (Postgres in WASM) otherwise, so previews have a working database with
  nothing configured. `getSql()` returns the same tagged-template surface either way.
- Migrations are flat `.sql` files in [migrations/](migrations/), applied **by basename** and
  recorded in `_migrations`, by two appliers sharing
  [scripts/migration-plan.mjs](scripts/migration-plan.mjs):
  [scripts/migrate.mjs](scripts/migrate.mjs) at build time (Neon) and `src/lib/db.ts` at startup
  (PGLite). Neither descends into subdirectories, so `migrations/auth/0001_auth.sql` stays
  inert until copied up. Put app schema in new ordered files (`0002_*.sql`), never in the auth one.
- Auth is Better Auth in [src/lib/auth/](src/lib/auth/). With auth ON, every server function
  takes `authMiddleware` and every query is scoped by the verified `context.userId` — never a
  client-sent id. With auth OFF, **do not import `authMiddleware`/`requireUserId` at all**: the
  dev user they resolve is preview-only and rejects every visitor once deployed.
- [src/lib/app-data/](src/lib/app-data/) is the viewer-connector client (Google Calendar/Drive
  etc.) served through the Grok gate, with its own login/readiness/error classification. The
  `app-data` skill AGENTS.md points at is not present in this workspace copy — read the module's
  own doc comments before wiring or refusing such an integration.

### Platform surfaces that must stay intact

- `grokPwaPlugin()` + [server/middleware/grok-pwa.ts](server/middleware/grok-pwa.ts) inject the
  PWA head, the manifest, `?install=1` tutorial, and the "Created with Grok / Remix" pill. Do not
  strip it, hide it with CSS, or add a CSP blocking `https://grok.com`. The injector also
  **overwrites `og:*`/`twitter:card` on every HTML response** — so never put those tags in
  [src/routes/__root.tsx](src/routes/__root.tsx). Share-card config lives in
  [src/lib/og/site.json](src/lib/og/site.json).
- `<PreviewHostBridge />` stays mounted near the top of `<body>`; it drives the app from the
  preview chrome over `postMessage` and is a silent noop anywhere else.
- `/auth/popup` is served by a Vite middleware in [vite.config.ts](vite.config.ts) — never create
  `src/routes/auth/popup.tsx`, it would paint the whole app inside the OAuth popup.
- Don't touch `public/__grok/`, `server/`, or `scripts/grok-pwa-*`. New server routes go in
  `src/routes/`, never `server/`.
- `vite.config.ts` port contracts (`0.0.0.0:8080` dev, `127.0.0.1:8081` preview) and the
  build/preview-gated nitro plugin are load-bearing; keep them if editing that file.

### Deploy

Target is Vercel. Things that work locally and fail there: runtime filesystem writes, server-only
Node APIs at import time, dev-only deps, hard-coded hosts/ports/secrets. Never create a `.env` —
the platform injects `DATABASE_URL` and auth credentials; only `VITE_`-prefixed vars reach the
browser. Details in `.grok/references/deploy-target.md`.

## Conventions

- `@/*` maps to `src/*`. TS is `strict` with `checkJs` on, so JSDoc types in `scripts/*.mjs` are
  typechecked too.
- Prettier: double quotes, semicolons, trailing commas, 100 cols. ESLint flat config; `any` is
  allowed, unused vars warn unless prefixed `_`.
- Unit tests are `node:test` with no framework. Logic that needs testing gets extracted into a
  plain `scripts/*.mjs` module (see `migration-plan.mjs`, `sign-out-plan.mjs`,
  `browser-smoke-verdict.mjs`) precisely so it can be tested without a browser or a server.
